# GeoCAD Tools 0.1

Интерпретируемый AutoLISP для AutoCAD и nanoCAD. `GCT_INFO` читает **одну LWPOLYLINE**, выводит вершины WCS, пример преобразования осей GEO, длины сторон, периметр, площадь и направление обхода. Исходный объект и координаты не изменяются. Нет COM, Visual LISP, компиляции, внешних пакетов, экспорта или оформления чертежа.

## Загрузка и первый тест

1. Скачайте каталог `geocad-tools` на компьютер с CAD.
2. Введите `APPLOAD`, загрузите **сначала** `src/gct-core.lsp`, **затем** `src/gct-cad.lsp`.
3. Для первого теста загрузите через `APPLOAD` также `tests/fixtures.lsp`.
4. Введите `GCT_FIXTURE`, затем `1` и Enter: создастся прямоугольник 10×20 и появится отчёт: площадь **200**, периметр **60**.
5. Введите `GCT_INFO` и щёлкните по стороне этого прямоугольника. Esc или пустой выбор отменяет команду.

Файлы сохранены в UTF-8. Для старых CAD без поддержки этой кодировки может потребоваться локальная копия в кодировке системы. Проверяйте русские сообщения после загрузки. Разрешите загрузку из доверенного каталога штатными настройками CAD; отключать защиту не требуется.

## Настройки

Все настройки находятся в начале `src/gct-core.lsp`:

| Переменная | По умолчанию | Значение |
|---|---|---|
| `gct:duplicate-tolerance` | `0.001` | Положительный допуск в единицах чертежа |
| `gct:output-precision` | `3` | Целое число знаков вывода 0..8 |
| `gct:geo-swap` | `T` | Geo_X=CAD_Y, Geo_Y=CAD_X; `nil` — без обмена |

Обмен осей — **пример настройки**, а не универсальное геодезическое правило и не преобразование системы координат. Проекции, датумы, единицы и коэффициенты масштаба автоматически не определяются. `rtos` используется только для текста; системные настройки CAD могут влиять на завершающие нули. Данные и промежуточные результаты не округляются.

## Геометрия и отказ от сомнительного результата

- Из DXF читаются вершины 10, признак замкнутости 70 (бит 1), высота 38, нормаль 210 и bulge 42. Каждая вершина передаётся как `(x y elevation)` в `(trans point entity 0)`: исходная система — OCS выбранного объекта, целевая — WCS. Текущая ПСК не используется.
- Отчёт содержит CAD_X/Y/**Z** в WCS. GEO использует WCS X/Y. Это **не геометрия для расчёта наклонного участка**.
- Длины и площадь считаются по XY **в плоскости OCS**. Ортонормированный переход в WCS сохраняет эти величины; проекция наклонного участка на WCS XY их не сохраняет. Обход CW/CCW относится к OCS, при взгляде со стороны положительной нормали. Обмен GEO-осей меняет знак ориентации в отображаемых осях, но не определение обхода отчёта.
- Знаковая площадь — формула Гаусса со смещением к первой вершине для уменьшения потери точности. В отчёте выводится абсолютная площадь.
- Любой ненулевой bulge: **«контур содержит дуги, расчёт не выполнен»**. Нет аппроксимации дуг.
- Незамкнутость, менее трёх вершин, дубли любых пар (включая первую и последнюю), пересечения/касания несоседних сторон и возврат соседних сторон блокируют расчёт. Вершины не удаляются и не исправляются.
- Площадь `<= допуск × периметр` считается сомнительной и блокируется. Проверки пересечений консервативно учитывают допуск: близкое касание может блокировать математически простой контур.
- При ошибке CAD команда сообщает, что результат не подтверждён. Ошибки данных не превращаются в нулевые итоговые значения.
- Ширина полилинии не участвует: граница задана её осевой линией. Значения выражены в единицах чертежа и их квадрате.

При `1e-14 × max(|X|, |Y|) > допуск` ядро дополнительно блокирует расчёт: масштаб координат не согласуется с требуемой точностью. Это консервативный порог, а не гарантия точности для любых экстремальных данных.

Алгоритмы проверки дублей и пересечений O(n²), рассчитаны на обычные участки, не на миллионы вершин. Используется машинная арифметика CAD, не точная рациональная арифметика; при экстремальных масштабах координат требуется отдельная проверка. Ядро принимает числовые списки XY; CAD-адаптер проверяет входные DXF-данные. Версия 0.1 не заменяет независимый кадастровый контроль.

## Проверки в облачной среде

Нужен только Python 3 (стандартная библиотека):

```sh
cd /workspace/Proekt/geocad-tools
python3 tests/reference.py
python3 tests/run_core.py
python3 tests/run_adapter.py
```

`reference.py` — независимые эталоны. `run_core.py` исполняет **сам файл ядра**, а не его перевод на Python, небольшим интерпретатором используемого подмножества AutoLISP. Это ограниченный тестовый инструмент; он не эмулирует CAD, `trans`, DXF или полную семантику AutoLISP. `run_adapter.py` проверяет контракт адаптера с подставными CAD-функциями, включая передачу elevation в `trans` и блокировку итогов при дугах/незамкнутости. Подробнее: [tests/README.md](tests/README.md).

## Что нужно проверить вручную в AutoCAD/nanoCAD

В облачной Linux-среде нет AutoCAD/nanoCAD: нативная загрузка и CAD-команды здесь **не проверены**. Выполните матрицу из `tests/README.md` в обоих продуктах и запишите версии/результаты.

Особенно проверьте `trans` с entity-name как системой OCS, DXF 210 и ненулевой 38; сохранение результата при смене ПСК; создание тестовой LWPOLYLINE через `entmake`; отмену выбора и обработчик ошибок; кодировку сообщений и формат `rtos`. Использованы стандартные базовые функции AutoLISP, но фактическая поддержка в вашей версии nanoCAD требует нативной проверки. До её выполнения совместимость считается целевой, а не подтверждённой.
