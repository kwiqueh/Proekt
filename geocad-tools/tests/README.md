# Проверки 0.1

## Автоматически, без CAD

`python3 tests/run_core.py` — проверки фактического исходника ядра ограниченным интерпретатором; `python3 tests/reference.py` — независимый эталон. Нет сторонних зависимостей. Проверяются длины каждой стороны, периметр, знаковая площадь, ориентация, номера дублей, блокировка открытых контуров, бабочки, дуг, малого числа вершин, возврата, касания, близких дублей, коллинеарности; прямоугольник также проверяется со смещением координат на 1e9.

`python3 tests/run_adapter.py` — 9 проверок CAD-адаптера с подставными `entget`, `trans`, `entsel`: флаги 70=129, координаты с высотой, открытый контур, дуги, несоответствие DXF 90, отказ от другого типа объекта и отмена выбора. Настоящий `trans` этим не проверяется.

## В каждом CAD отдельно

Загрузить через APPLOAD core, cad, fixtures в таком порядке. Для каждой строки вызвать `GCT_FIXTURE` и ввести номер. Тесты создают объекты в текущем чертеже, поэтому использовать отдельный пустой файл; объекты накладываются друг на друга. Для чистой проверки выбора удобно начинать каждый тест в новом чертеже.

| № | Фигура | Ожидаемый результат |
|---|---|---|
| 1 | (0,0), (10,0), (10,20), (0,20) | Стороны 10/20/10/20; P=60; A=200; CCW |
| 2 | Вершины №1 в обратном порядке | P=60; A=200; знаковая A=-200; CW |
| 3 | Вершина (10,0) повторена подряд | Дубли 2,3; предупреждение, итогов нет |
| 4 | №1, DXF 70=0 | Предупреждение о незамкнутости, итогов нет |
| 5 | (0,0), (10,20), (0,20), (10,0) | Некорректный контур/пересечение, итогов нет |
| 6 | №1 в OCS, нормаль (0,1,0), высота 7 | WCS ниже; P=60; A=200; CCW в OCS |
| 7 | №1, первый bulge=0.5 | «контур содержит дуги, расчёт не выполнен»; итогов нет |

№3: Python выводит диагностические A=200 и P=60 для исходного списка, **но CAD-команда обязана отказаться от расчёта**.

№6: ожидаемые WCS вершины `(0,7,0), (-10,7,0), (-10,7,20), (0,7,20)`; GEO при настройке по умолчанию `(7,0), (7,-10), (7,-10), (7,0)`. Совпадение GEO-проекций здесь нормально: участок вертикальный. Его площадь в плоскости равна 200, площадь WCS XY-проекции равна 0 и не используется.

Для №6 изменить ПСК штатной командой UCS: начало (100,200,30), поворот вокруг Z на 30 градусов. Затем вызвать `GCT_CHECK6`: ожидается `PASS: test 6 WCS (trans)`. Повторить в мировой ПСК: значения должны совпасть. В обоих случаях функция создаёт тестовый объект; проверка `equal` использует 1e-9. Отдельно проверить обычный горизонтальный контур с DXF 38=7, нормалью (0,0,1): WCS Z каждой вершины равен 7. Изменение ПСК само по себе не изменяет DXF-геометрию.

Дополнительно: `GCT_INFO` → Esc; Enter без выбора; выбор LINE, окружности, старой POLYLINE; контур с флагом 70=129 (бит замкнутости должен учитываться); повтор начальной вершины в конце; коллинеарные точки; отрицательная нормаль; координаты 1e9; точность 0 и 8. Ни одна проверка не должна изменять исходные вершины.

Результаты нативных тестов: **не выполнены в облаке**, требуется AutoCAD/nanoCAD. После запуска фиксировать продукт, версию, кодировку, тест, факт/ожидание и PASS/FAIL. Запуск Python не доказывает корректность реализации `trans` в CAD.
